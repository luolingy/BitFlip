## 2. 本轮已实现：单基本块表达式视图

模块：`crates/bitflip-analyze/src/pseudo.rs`

### 它做什么

- 把每条指令翻译成一句 C 风格语句，**每条语句带来源指令地址**；
- 寄存器、内存引用写成可核对的形式（`*(uint32_t *)(rax + 0x10)`）；
- 条件跳转原样写成 `if (flags) goto 0x1100;`，**不还原成 if/while/for**。

### 它明确不做什么（都有测试锁住）

- **不做控制流结构化** —— `structured` 字段恒为 `false`，且必定产出 `FlatGoto` 说明。
  写成字段而不是省略，是为了让调用方不必猜当前输出的语义级别。
- **不编造名字** —— 符号表里没有名字就输出入口地址，测试断言输出里不含 `func_`。
- **不猜未知目标** —— 间接跳转写明"目标未知"，不编一个地址。
- **不编造寄存器名** —— 名字表未覆盖的架构返回 `None` 并报 `RegistersUnnamed`，
  而不是打印一个看起来像名字的东西。目前**只覆盖 x86_64 通用寄存器**，
  宁可在其他架构上明说未覆盖（错的寄存器名比编号更糟）。
- **宽度是事实不是猜测** —— `uint32_t` 来自 `MemRef::size`；
  非 1/2/4/8 的宽度如实标注"12 字节"，不硬塞 C 类型。

### 为什么切在这里

这条线以内，**每一句都能追溯到一条真实指令**；线以外做不到。
输出 `while` 循环时用户无法判断那是真的循环还是我们猜的；
输出 `if (flags) goto 0x1100;` 时，`flags` 来自哪条指令、
`0x1100` 是哪个跳转目标，都可核对。

**这不是"退而求其次"，而是当前唯一能同时满足"有用"与"说的是真的"的位置。**
调研里有官方先例：radare2 的 `pdc` 就是这一档，官方描述其
"不实现任何控制流改进，也不做优化"，定位"顺手、快"。

## 3. 为什么不做控制流结构化

三条理由，按分量排序：

### 3.1 理论上的不可判定（最根本）

SAILR 论文原文：反编译器做出的许多结构化选择**"在最终意义上是不可判定的"**。
根源是源码→二进制是**多对一**映射，其逆不唯一 —— 所以不存在"正确"的结构，
只有"更可能的"。一个输出 `while` 的反编译器，无论多好，都在**猜**。
这与 `CLAUDE.md` §7「说的就是真的」直接冲突。

### 3.2 消除 goto 是错的（反直觉但已证实）

SAILR 实测 7 355 个函数（Linux kernel 6.1）：

| 工具 | goto 数 | 结构相似度（越低越好） |
| --- | --- | --- |
| 原始源码 | 1 367 | — |
| CFGED | **0** | — |
| Hex-Rays | 6 115 | 22.52 |
| SAILR | 2 673 | **22.64** |
| DREAM | **0** | **45.99** |

DREAM 做到了零 goto，**但结构相似度翻倍恶化**。追求"看起来干净"会得到
"事实上更错"的结果 —— 这正是我们最该避免的失败模式。

### 3.3 有实证的静默失败

- RET2《Dangers of the Decompiler》：栈枢轴 + `noreturn` 劫持可让反编译器
  **不报错、不给警告，只是静默隐藏代码**。
- 实战案例：Ghidra 因 3 MB 栈帧静默没定义栈变量，导致输出里**整条 `xor` 消失**
  （而那正是拿 flag 的关键）。
- 这与 §7「降级要写在界面上……不能悄悄少给数据」**直接冲突**。

对照组的正确做法：IDA 在 Positive SP Value 时**拒绝反编译**。
本轮 `pseudo` 的做法与之一致 —— 翻不了就写 `/* 无法翻译：原因 */` 并计数。

## 4. 下一轮待办

### 4.1 类型展示（不推断）—— 投入产出比最高

我们已有 DWARF/PDB 解析（`bitflip-debug`），类型是**读来的而不是猜的**。
每个类型必须标注来源：`from_dwarf` / `from_pdb` / `unknown`；
无调试信息时显示 `[unknown]` + 原因，且优先展示原始位置（`[rbp-0x14]`）
而不是捏造变量名。

### 4.2 `koute/ghidra-decompiler` spike —— 唯一可能改变结论的变量

这是 Ghidra 反编译器核心（Ghidra 12.2, `decompile/cpp`）的**纯 Rust 移植**：
Apache-2.0、**零 FFI**、零 C/C++/Java 依赖、依赖仅 6 个小 crate。
default features 是 x86/arm/aarch64/mips/powerpc/riscv —— **与我们现有 capstone
架构几乎完全重合**。

**风险很大，必须先验证**：星标仅 6、2025-09 创建、单人项目、
README 首行自述"由 agent 自动从 Ghidra C++ 源码移植"、无社区验证。
**调研未编译、未运行，其"输出与 C++ 逐字相同"的说法未独立验证。**

spike 内容：用我们自己的 fixtures 在 x86/aarch64 上跑 `-O0`/`-O2`，
与真实 Ghidra 输出逐字对比；**重点检查它是否违反 §7**
（生成 `func_xxx` 占位名、把未知字段当 0、静默少给数据）。
几乎肯定会违反 —— 所以产出物是"必须做的适配/包装清单"。

**若可用**，决策从"写反编译器"变成"给反编译器输出套一层诚实性外壳"，
量级完全不同；**若不可用**，维持"不做"，只保留 §2 的表达式视图。

### 4.3 明确不排期

- 控制流结构化（§3）。
- 从零自研完整反编译器：Ghidra 核心移植到 Rust 后是 **6.1 MB** 代码；
  RetDec **14.4 MB C++** 且已进入 limited maintenance；
  Snowman **1.6 MB** 且**仓库已被作者抹除**；
  最贴近的先例 radeco（Rust，4+ 年、多个 GSoC）被 radare2 官方书籍标记为
  **"experimental and abandoned"**。这条路的历史成功率是零。

## 5. 诚实性基础设施（独立于反编译决策）

调研建议的一条，本身即有价值，**不需要反编译器就能落地**。
现在已经有了第一块：

1. **每个值携带来源地址** —— ✅ 已落地：`PseudocodeStatement::addr`，
   测试 `every_statement_traces_to_an_instruction_address` 锁住。
   （借鉴 Ghidra step14：每个 token 关联其机器指令地址，是机器码/C 交叉高亮的基础。）
2. **区分 `identified | inferred | unknown`** —— 待办。可从 `docs/PLAN.md`
   已有的"未识别"概念扩展。
3. **失败显式化** —— ✅ 已落地：`PseudocodeNote::Untranslated` + `untranslated` 计数，
   翻不了就如实报告。
4. **降级可见化** —— ✅ 已落地：`PseudocodeNote` 的每一类都会渲染进输出。
