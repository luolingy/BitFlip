# BitFlip 能力矩阵与已知边界

> 本页是**发布说明用**的一页纸：当前能做什么、做到什么程度、哪些明确不做或未验证。
> 每条都力求可核对。逐里程碑的实现细节与验收证据见 [`PLAN.md`](PLAN.md)；
> 与 IDA 的逐条差距见 [`FORMAT-COVERAGE-VS-IDA.md`](FORMAT-COVERAGE-VS-IDA.md)。

## 1. 格式与架构

| 类别 | 状态 | 说明 |
| --- | --- | --- |
| PE32 / PE32+ | ✅ 完整 | 段/节、导入(IAT/ILT)/导出(含转发)/重定位、`.pdata` 展开信息 |
| COFF `.obj` | ✅ | 与 PE 共用对象层 |
| 静态库 `.lib` / `ar` `.a` | ✅ | 类型 1/2 成员链、长名表、符号索引、按成员分析 |
| ELF32 / ELF64 | ✅ | exec/.so/.o、`.symtab`/`.dynsym`、`PT_DYNAMIC`、PLT/GOT、`.eh_frame` |
| raw / 固件 | ✅ | 手工基址/段定义；`--arch`/`--mode`/`--endian`/`--base`/`--force-raw` |
| Mach-O thin / fat | ✅ | 头/段/节/入口/`LC_UUID`/dylib/`LC_SYMTAB`/`LC_FUNCTION_STARTS`/chained fixups |
| Mach-O 元数据 | ✅ | ObjC 选择器/方法表/消息桩/类与类别；Swift 元数据；dyld 绑定导入 |
| 代码签名 | ◐ | **有界完整性校验** + entitlements/requirements 事实；**不校信任链、不校封印** |
| `.app` bundle / `.ipa` | ✅ | 目录容器递归枚举；IPA = ZIP + `.app` |
| 重签（ad-hoc） | ✅ | 单二进制 + fat + `.app` 批量 + CodeResources 自洽；**不做带证书的正式重签** |
| APK（ZIP 容器） | ✅ | 成员枚举、`lib/<abi>/*.so` 复用 ELF 路径 |
| DEX（`classes*.dex`） | ✅ | 结构模型、字节码解码、CFG、交叉引用、smali 文本；多 dex 分 tab |
| AndroidManifest（AXML） | ✅ | 字段摘要 + 还原 XML；解不出的资源引用原样保留并计数 |
| resources.arsc | ◐ | 结构快照（包/类型/配置/条目）+ 按 id 查值；值解码有限 |
| .NET 程序集 | ◐ | 仅识别（PE + CLI header），不做 CIL 反编译 |

**架构**（capstone 单后端）：x86、x86_64、ARM、Thumb、AArch64、RISC-V 32/64、
MIPS、MIPS64、PowerPC、PowerPC64。`Wasm32` 枚举已定义但**未实现**（明确报未支持）。

## 2. 分析能力

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 反汇编 | ✅ | 线性扫描 + 递归下降双策略；可达性分层显示（仅线性覆盖调暗） |
| 函数识别 | ✅ | 多来源 + 置信度（用户 > 符号表 > 展开表 > 函数起点 > 签名 > 调试信息 > 探索） |
| 交叉引用 | ✅ | call/jump/data，区分 `direct` 与 `jump-table` 推导；全表过滤 + 分页 |
| 调用图 | ✅ | 领域查询为主路径；未解析的间接调用单列计数 |
| 跳转表 / switch | ✅ | 目标集合与编译器黄金值逐项比对 |
| 数据/代码判定 | ✅ | `Code/Data/Unknown` 三态 + 逐条证据；`Unknown` 是一等公民 |
| 常量/结构体初步 | ✅ | 字符串引用聚合、访问步长、高频立即数；**只给观测，不给字段名/类型** |
| 调用约定/参数推断 | ✅ | 只给下界（"≥ N 个"），不给确切个数 |
| 栈帧 / 局部变量 | ✅ | 展开信息 + 前导扫描，两来源分开给值 |
| 可达性 | ✅ | BFS 下界；`unreachable` 与 `unresolved_indirect` 并排显示（不可达≠死代码） |
| DWARF / PDB / CodeView | ✅ | 函数名/精确边界/声明行/源文件贯通到反汇编、函数表、xref、调用图 |
| MSVC 名字反修饰 | ✅ | 显示名可读，原始修饰名作为 `aliases` 保留（改显示不改身份） |
| 签名库（FLIRT 风格） | ✅ | 从可重定位对象抽指纹；本地派生、不预置数据库 |
| 内置模式库 | ◐ | 目前仅 GCC `___chkstk_ms` 等少数硬判据 |
| 伪代码（单基本块表达式视图） | ✅ | 每条语句带来源指令地址；**不做控制流结构化**（见下） |

## 3. 带出与写回

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 导出 | ✅ | 反汇编（Intel/AT&T）、函数/符号/xref/结构体/库/调用图/可达性 JSON、CFG/DOT、伪代码、DEX；17 种格式 |
| 导出账目 | ✅ | 每个导出自述格式版本、条数、截断与降级说明 |
| 差分 | ✅ | 函数/节/符号/指令级；RVA 归一化、强/弱双指纹、三态内容判定、配对判据 |
| 打补丁 | ✅ | plan/validate/apply；默认只读、显式 unlock、只写副本、原子写、PE CheckSum 重算 |
| 补丁可执行验证 | ◐ | PE 已真跑验收（补丁后副本执行输出变化）；**ELF 未在可跑环境验证** |
| 脚本层 | ✅ | rquickjs；读/写标注、自定义表、进度；**不注册分析 pass**（刻意不给空壳） |

## 4. 明确不做（非目标，做了会跑偏）

- 完整 C 伪代码反编译 / 控制流结构化（不可判定；见 ADR-0018 与 `DECOMPILER-SCOPE.md`）。
- `.NET`/CIL 反编译；Smali↔DEX 双向；APK/IPA 重打包与**重签名**（只做 ad-hoc 重签）。
- 正式 Mach-O 重签（带 CMS/开发者身份/私钥），需单独立项与密钥隔离。
- 动态调试器、仿真、符号执行、沙箱。
- IDA/Ghidra 数据库格式互操作（只做导出）。
- 150 种历史/嵌入式架构（按目标场景补，不按对标 IDA 补）。
- DEX v041 容器格式 / ODEX / VDEX / CompactDex（遇到真实样本再做；解析器遇到明确报"版本尚未支持"）。

## 5. 已知的诚实的"未做 / 未验证"

以下条目**不是缺陷**，而是按"不猜测、不编造"原则刻意保留为"未做/未验证"，且大多在
界面或输出里如实说明：

1. AArch64 的 IC/DC/AT/TLBI 子操作名（210 条表）、`prfm` 预取类型 —— 显示为
   `<sys_op:N>` / `<prefetch:?>`，不编名字。
2. 反编译器类型展示（不推断）、外部反编译器接入（spike 实测不通过诚实性门槛，不接）。
3. 静态库成员的 PDB（只做镜像本身的 PDB）。
4. DEX 覆盖率引导 fuzz / 长时间 soak（有结构化 fuzz，未接 cargo-fuzz/AFL）。
5. 跨归档成员的 xref 图（成员各自独立地址空间，需符号名连接）。
6. Web 端对 `resign`（重签）、`structs`（结构体）尚无专用视图，走 CLI。
7. 端到端 UI 冒烟（Playwright 主链路）—— 见 CHANGELOG 的发布说明。

## 6. 与"正式版"的关系

本项目的完成判据是**收敛**而非扩张：承诺的每条能力都真实可用、每条没做到的都如实说明。
上述"未做/未验证"项全部被记录为边界，而非隐藏缺陷 —— 这正是 BitFlip 的定位（本地优先、
诚实降级），而不是背离。逐条发布判据见 `PLAN.md` 与仓库根 `CHANGELOG.md`。
